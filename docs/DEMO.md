# Демо для стоматолога: сценарий показа

Три акта по четыре минуты, каждый закрывает одно возражение:

1. «наши пациенты звонят, а не пишут» → бот записывает сам, ночью, с опечатками,
   и владелец видит запись в момент, когда она случилась;
2. «дорого» → отменённый слот возвращается в продажу, деньги видно в сводке;
3. «а если бот ошибётся с живым пациентом» → он не выдумывает: зовёт вас, а вы
   отвечаете пациенту, не выходя из своего же чата.

Всё остальное — резерв, доставать только под вопрос. Работает с ноутбука;
деплой на сервер ничего не меняет, кроме адреса.

## Подготовка (за час до встречи)

### 1. База, витрина, чеклист

```powershell
docker compose up -d
alembic upgrade head                     # код новее базы = молчаливые падения
python -m navbat.onboard --demo          # демо-клиника + токен из .env (идемпотентно)
python -m navbat.onboard --clinic 00000000-0000-4000-8000-000000000d31 --address "Ташкент, ул. Навои, 10"
python -m navbat.onboard --clinic 00000000-0000-4000-8000-000000000d31 --payment "Наличные, карта, Payme. Рассрочки нет" --phone "+998 71 200-00-00"
python -m navbat.onboard --clinic 00000000-0000-4000-8000-000000000d31 --review-url "https://g.page/r/ВАША-ССЫЛКА/review"
python -m navbat.onboard --demo-history  # история для /stats (акт 2)
python -m navbat --check                 # все строки должны быть [OK]
```

**Витрину стирает ЛЮБОЙ прогон pytest — даже одного файла**: фикстуры чистят
базу целиком. Финализатор сьюта восстанавливает клинику и токен (`--demo`), но
НЕ историю. Поэтому `--demo-history` — последняя команда подготовки, после всех
тестов; за час до встречи проверьте `/stats 7` глазами. Живой прогон 31.07:
четыре точечных теста обнулили все 74 записи истории, и сводка показала
«записей: 2».

`--demo-history` наполняет ПРОШЛЫЕ две недели работой бота: записи (часть
оформлена ночью), отмены из напоминания с суммой освобождённых слотов, новые и
вернувшиеся клиенты. Без неё акт 2 показывает нули по всем строкам — денежный
аргумент выглядит пустым экраном. Команда идемпотентна и трогает только
прошлое: слоты, которые вы показываете вживую, остаются свободными. Перед
КАЖДЫМ показом её стоит повторить: дни с историей она не тронет, а натёкшие с
прошлого раза наполнит — иначе свежая неделя в сводке окажется пустой. Вместе
с записями сеются журналы возвратов и оценок: строки «🔁 Возврат пациентов»
(приглашений, вернулось, сумма) и «⭐ Оценки пациентов» (средняя, число оценок)
в `/stats 7` живые. НЕ сеется только очередь ожидания — строки «🔔 в очереди»
не будет (витрина не показывает нулей: пустых строк там нет вовсе). В Google
Calendar история тоже не уходит — там остаются только настоящие записи показа.

Показ КОНКРЕТНОМУ центру — переименуйте демо-клинику: первый экран бота несёт
вывеску, и «🦷 Shifo Dent» психологически уже их бот, а не чей-то продукт:

```powershell
python -m navbat.onboard --clinic 00000000-0000-4000-8000-000000000d31 --name "Shifo Dent"
```

### 2. Повторный визит — включить ДО показа

В админ-чате напишите что угодно → откроется консоль → «💊 Услуги» → «Чистка» →
в карточке ряд кнопок «🔁 Выкл | 3 мес | 6 мес | 12 мес» → «6 мес». То же для
«Осмотр» → «12 мес». В карточке появится строка «🔁 Повторный визит: 6 мес» —
на показе вы ОТКРЫВАЕТЕ этот экран, а не рассказываете про настройку абстрактно.

Саму рассылку вживую увидеть нельзя: приглашение уходит, когда после приёма
прошли назначенные месяцы. То же с отзывами: просьба об оценке уходит через
2 часа после ОКОНЧАНИЯ приёма (и не позже 48 часов, только в 09:00–21:00 по
клинике). За 15 минут показа такого приёма не случится. Обещать «сейчас
увидите» нельзя — не увидит. Но ЦИФРЫ обеих фич в `/stats 7` есть — их сеет
демо-история (п. 1): рассказ на 30 секунд в конце акта 3 идёт с открытой
сводкой, пальцем по строкам «🔁 приглашений N, вернулось M (≈ сумма)» и
«⭐ средняя», плюс экран настройки интервала в карточке услуги.

### 3. Телеграм-бот (один раз)

- @BotFather → `/newbot` → токен;
- свой chat id — написать @userinfobot;
- `python -m navbat.onboard --clinic 00000000-0000-4000-8000-000000000d31
  --tg-token <токен> --admin-chat <ваш chat id>`.

### 4. Google Calendar (опционально, сильный ход)

- `python -m navbat.calendar.auth --clinic <id>` — авторизация Google;
- `python -m navbat.onboard --clinic <id> --list` — взять id врача;
- `python -m navbat.onboard --clinic <id> --doctor <id> --calendar <календарь>`.

**Делать в день показа, не раньше.** Пока приложение Google не прошло
верификацию (consent screen в testing-режиме), refresh-токен живёт 7 дней —
привязка, сделанная неделей раньше, к встрече умрёт. Любой полный `pytest` тоже
стирает привязку вместе с базой, поэтому шаг повторяется ПОСЛЕ прогона тестов.

**Календарь брать отдельный, не личный `primary`.** Живой прогон 31.07:
привязка к личному календарю затянула в занятость 9 посторонних событий
владельца — они закрывают слоты, которые вы собираетесь показывать, а старые
пересекающиеся события шлют администратору операционные сигналы ещё на старте.
Заведите в Google отдельный календарь на врача. Что именно сломалось, покажет
`--check`: он различает «не настроен», «токен есть, но не привязан ни одному
врачу» и «привязан только скрытым».

### 5. Запуск на время демо

```powershell
python -m navbat --real --reminder-offsets 4,2
```

Офсеты — минуты до приёма: напоминание придёт за 4 и за 2 минуты, поэтому
запись акта 2 должна быть минимум через 4 минуты от «сейчас».

Сбросьте следы репетиции: отмените тестовые записи через бота или пересоздайте
демо-клинику.

### 6. Пациентский телефон — ЧУЖОЙ, не ваш

**Пациентские шаги показывать с ЧУЖОГО телефона.** Три причины, все проверены
живьём 31.07: со своего аккаунта (он же админ-чат) бот включает админ-консоль
вместо диалога пациента; строка «p95 ответа» в сводке не появится вовсе —
админские сообщения из пациентской метрики исключены; а эскалация и карточки
не дойдут, потому что отправитель и получатель совпадают. Один чужой телефон
закрывает все три акта.

## Что показывается вживую, а что словами

| Вживую | Словами (с открытым экраном) |
|---|---|
| Запись свободным текстом, календарь месяца, телефон кнопкой | Утренняя сводка в 08:30 (её видно только утром) |
| Карточки ленты ✅ / ❌ / 🔄 в админ-чате | Приглашение на повторный визит (уходит через месяцы; цифры — в `/stats`) |
| Напоминание, отмена из него, освободившийся слот | Просьба об оценке ⭐ (через 2 ч после приёма; средняя — в `/stats`) |
| Экран «📅 Сегодня» с ✅/⏳ и «стоит позвонить» | Лист ожидания (кнопка появляется, когда 2 недели пусты) |
| `/stats 7` — деньги за неделю | |
| Эскалация, ответ владельца свайпом, `/release` | |

## АКТ 1. Клиника получает пациента ночью (~4 мин)

Держите свой телефон с админ-чатом на виду: половина эффекта акта — в том, что
владелец видит запись у себя, пока пациент ещё читает подтверждение.

1. **С чужого телефона пишете боту свободной фразой, можно с опечатками:**
   «алло здравствуйте мне бы на чистку завтра после обеда».
   → *Понимает узбекский, русский и смесь — как пишут реальные пациенты. Это
   работает в 3 часа ночи, когда администратор спит.*

   **Узбекский показывать только из чистого чата или сначала переключив
   «🌐 Til / Язык»**: язык у чата липкий, и после русского бот продолжит
   отвечать по-русски на «ertaga tish tozalashga yozilsam bo'ladimi» — врач
   прочтёт это как «узбекский не понимает» (проверено живьём 31.07).

2. **Бот предлагает слоты кнопками — НЕ жмёте время, а жмёте «Другое время» →
   «📅 Выбрать дату».**
   → *Вау-момент: календарь месяца прямо в чате. «•» — дни, где реально есть
   время. Листается стрелками, всё считается из живого графика врачей.*

3. **Жмёте «•»-день → весь день сеткой времени → выбираете слот.**
   → *Слоты настоящие: график врачей, обед, буфер между приёмами. Два пациента
   один слот не возьмут никогда.*

4. **Имя, затем телефон кнопкой «📱 Отправить мой номер» — одно нажатие.**
   Приходит «✅ ЗАПИСЬ ПОДТВЕРЖДЕНА» с услугой, датой, врачом и адресом.
   → *Номер берётся прямо из Telegram: пациент не ошибётся в цифрах, чужой
   контакт бот не примет, иностранная симка — не проблема. Телефон хранится
   зашифрованным, в интернет имена не уходят.*

5. **Разворачиваете свой телефон — в админ-чате уже лежит карточка:**
   «✅ Запись: Алишер, Чистка, 04.08 15:00, Akmal aka».
   → *Вы видите каждую запись в момент, когда она случилась, — хоть в 3 часа
   ночи. Ничего не надо открывать: ни календарь, ни админку.*

   Пометка 🌙 ставится, если запись оформлена ВНЕ рабочих часов клиники (до
   09:00, после 18:00, в закрытый день). Днём её не будет — не обещайте её
   заранее; «бот работает ночью» подкрепит строка в `/stats` из акта 2. Вечерний
   показ или воскресенье — 🌙 появится сама.

## АКТ 2. Navbat спасает слот (~4 мин)

1. **С того же телефона: «запишите на сегодня на осмотр».** Бот УЗНАЁТ пациента —
   имя и телефон больше не спрашивает, запись в два тапа. Берите ближайший слот,
   но не ближе чем через 4 минуты (иначе напоминание уже не успеет).
   → *Постоянного пациента бот помнит: повторная запись — два касания.*

2. **В админ-чате: кнопка «📅 Сегодня» (или команда `/today`).** Приходит день
   клиники: время, имя, телефон, услуга, врач.
   → *Клинике без Google Calendar это заменяет журнал: весь день с телефонами
   на одном экране.*

3. **Ждём напоминание** (за 4 и за 2 минуты до приёма — на живой клинике это за
   24 часа и за 2 часа). Пока ждём, жмёте под экраном дня «🔄 Обновить» —
   после того как напоминание ушло, у строки появляется ⏳, а сверху
   «⚠️ Без ответа после напоминания: 1 — стоит позвонить».
   → *Бот показывает не «кто записан», а что делать: ✅ подтвердил, ⏳ молчит.
   Ровно этот экран приходит вам сам каждое утро в 08:30 — список дня и кому
   стоит позвонить.*

4. **На телефоне пациента жмёте «Отменить запись» → «Да, отменить».**
   **Жмите именно «Отменить», не «✓ Приду»**: метрика «предотвращено неявок»
   считает только отмены из напоминания, с «Приду» денежная строка в сводке
   останется нулевой (а «Приду» вы покажете в резерве, если спросят).
   → *Вместо неявки — свободное время, которое ещё можно продать.*

5. **В админ-чате: карточка «❌ Отмена: …», жмёте «🔄 Обновить» — строка ушла
   из дня.** По желанию: с телефона пациента «запишите на сегодня» — то самое
   время снова в кнопках, два тапа, и в чат падает новая «✅ Запись».
   → *Слот не пропал вместе с пациентом: он вернулся в продажу в ту же секунду.*

6. **`/stats 7`** (или кнопка «📊 Статистика» → **«7 дней»**: сама кнопка
   открывает сводку за СЕГОДНЯ, а утром она законно пуста).
   → *Деньги за неделю: записи и сколько из них пришло вне рабочих часов,
   предотвращённые неявки в сумах, эскалаций: 0. Ниже — новые и вернувшиеся
   клиенты, топ врачей с суммой по прейскуранту, хит-услуга, тренды ↑↓ к
   прошлой неделе. Кнопки «📅 День / 7 дней / 30 дней» переключают период прямо
   в сообщении. Каждый вечер короткая сводка приходит сама — вместе с
   вопросами, на которые бот не нашёл ответа.*

> Порядок «сначала деньги, потом эскалация» важен: эскалация из акта 3 попадает
> в счётчик, и показанная ПОСЛЕ неё сводка выдаст «эскалаций: 1» ровно под
> слова «администратора бот не дёргает».

## АКТ 3. AI не рискует репутацией (~4 мин)

1. **С телефона пациента: «позовите администратора».**
   Пациент видит «👤 Передаю администратору — он ответит вам здесь в ближайшее
   время» и кнопку «↩️ Вернуться к записи».
   → *Единственный способ дёрнуть человека — попросить человека. Бот на этом
   замолкает и ничего не выдумывает.*

2. **В админ-чате — алерт с контекстом:**
   «Эскалация: чат 12345 / Причина: пациент просит администратора / Что хотел
   пациент: услуга — Чистка; день — 04.08 / Снять: /release 12345».
   → *Вы получаете не «вам пишут», а что человек успел выбрать.*

3. **Пациент пишет дальше:** «у меня зуб разболелся, можно раньше?» — в
   админ-чат падает карточка «💬 Чат 12345: у меня зуб разболелся, можно раньше?».
   → *Пока пациент ждёт вас, он пишет не в пустоту — каждая его реплика у вас
   на экране.*

4. **ВЛАДЕЛЕЦ САМ отвечает свайп-реплаем** на эту карточку (или на алерт) —
   пусть напишет своими словами, это ключевой момент показа. Пациенту приходит
   «👤 Администратор: приходите к 14:00, примем вне очереди», владельцу —
   «✅ Доставлено».
   → *Вы отвечаете пациенту из своего же чата, ничего не устанавливая и не
   спрашивая у него номер. Он видит, что говорит с человеком, — подпись
   «Администратор» стоит всегда.*

5. **`/release 12345`** — бот возвращается, пациент получает меню.
   → *Разговор закончен — одна команда, и дальше опять работает бот.*

6. **30 секунд «что происходит дальше без вас»** (говорите, экраны уже не нужны,
   кроме карточки услуги с «🔁 Повторный визит»):
   - в 08:30 приходит сводка дня — список приёмов и кто не ответил на
     напоминание;
   - напоминания уходят за сутки и за два часа, отмена освобождает слот сама;
   - через полгода после чистки бот сам напишет пациенту «пора показаться
     врачу» — вот этот переключатель в карточке услуги, интервал 3/6/12
     месяцев. А вот что канал даёт: строка «🔁 Возврат пациентов» в `/stats 7`
     — приглашений, вернулось, сумма. Выручка из уже оплаченной базы;
   - через пару часов после приёма бот спросит оценку от 1 до 5. Пятёрка ведёт
     на вашу страницу отзывов, а двойка приходит ВАМ в этот чат — и отвечаете
     вы тем же свайпом. Негатив попадает к вам, а не в 2ГИС. Средняя и число
     оценок — строка «⭐ Оценки пациентов» там же, в `/stats 7`.

## Резерв на вопросы

Не показывать по своей инициативе — только когда спросят.

- **«А бытовые вопросы?»** — «сколько стоит отбеливание?», «где вы находитесь?»,
  «рассрочка есть?», «какой у вас номер?», затем кнопка «ℹ️ О клинике». Цены из
  прайса, остальное из настроек, карточка собирает всё вместе. Ни одного вызова
  ИИ и ни одного обращения к администратору.
- **«А если попросят нерабочее время?»** — «**завтра** в 21:00 можно?»: бот
  честно говорит, что клиника работает с 09:00 до 18:00, и сразу предлагает
  варианты. День в вопросе обязателен: без него («а в 21:00 можно?») бот
  сначала спросит, на какой день, и строки про часы не будет (проверено 31.07).
- **«А переспросить про другое время?»** — «а ещё варианты есть?» → снова выбор
  дня. Раньше такие вопросы дёргали администратора.
- **Перенос** — «перенесите мою запись на послезавтра» → новые слоты →
  «✅ ПЕРЕНЕСЕНО», в админ-чат уходит карточка «🔄 Перенос».
- **Google Calendar** — запись уже в календаре врача: «Отбеливание — Алишер
  (Navbat)», телефон в описании. Создайте руками событие поверх записи бота:
  живая запись главнее, бот сам перенесёт своего пациента на ближайшее время и
  извинится, а владельцу пришлёт карточку «🔄 Перенос».
- **«✓ Приду»** — вторая кнопка напоминания: пациент подтверждает визит, и в
  экране «📅 Сегодня» его строка получает ✅ вместо ⏳. Для денежной строки
  сводки нужна именно отмена, поэтому в акте 2 жмут «Отменить».
- **Пауза** — `/pause Ремонт` в админ-чате: пациентам бот отвечает «Запись через
  бота временно приостановлена. Позвоните в клинику: +998 71 200-00-00» (номер
  подставляется, если задан `--phone`; не задан — просто «позвоните в клинику»).
  Возврат — `/resume`. Консоль и команды работают и на паузе.
- **Лист ожидания** — когда времени нет, пациент жмёт «🔔 Сообщить, когда
  освободится», и при первой же отмене бот сам присылает ему освободившийся слот
  кнопкой: один тап — записан. **Вживую на демо-клинике не показывается**:
  кнопка появляется, только когда по услуге НЕТ свободного времени на две
  недели вперёд, а у демо-клиники график пустой. У живой клиники с плотным
  расписанием она появляется сама. Вторая грабля (если всё же показываете на
  забитом графике): не вставайте в очередь на услугу, на которую только что
  записались, — у пациента с будущей записью матчер молча закрывает очередь и
  пуш не придёт.
- **Повторный визит и отзывы** — сам процесс не вживую (см. «Подготовка»,
  п. 2), но цифры обеих фич живые в `/stats 7` — показывать строки 🔁 и ⭐.

## Чеклист онбординга — 5 тест-диалогов

Прогоняется ПЕРЕД передачей бота живой клинике (после онбординга, с её ботом,
прайсом и адресом). Каждый пункт должен пройти без эскалации:

1. **Запись на узбекском**: «ertaga tish tozalashga yozilsam bo'ladimi» → слоты
   → выбор → имя → телефон кнопкой → подтверждение. Проверить запись в
   `--list`/календаре И карточку «✅ Запись» в админ-чате клиники.
2. **Календарь**: «Другое время» → «📅 Выбрать дату» → «•»-дни совпадают с
   графиком врачей, выходной пуст; листание ▶ работает, в прошлое не уходит;
   выбор «•»-дня → сетка времени → запись.
3. **Бытовые вопросы**: «сколько стоит отбеливание?», «manzil?», «до скольки
   работаете?», «рассрочка есть?» → цена/адрес/часы/оплата без эскалации;
   кнопка «ℹ️ О клинике» → карточка только с заполненными полями; «а в 21
   можно?» → строка про рабочие часы.
4. **Перенос и отмена**: «перенесите мою запись на послезавтра» → новые слоты →
   подтверждение + карточка «🔄 Перенос»; отмена кнопкой из напоминания → слот
   освобождён + карточка «❌ Отмена». Через 2–3 часа после реального приёма
   проверить, что пациенту пришла просьба об оценке со звёздами (только по
   записям, сделанным через бота: ручные события врача из календаря бот не
   трогает), а оценка 1–3 упала алертом в админ-чат.
5. **Админ-чат**: `/today` показывает день с телефонами и значками ✅/⏳;
   `/stats 7` показывает деньги недели; ерунда от пациента → «не понял» с
   кнопкой «👤 Позвать администратора», тап → алерт, **свайп-реплай на алерт
   доходит пациенту** как «👤 Администратор: …», `/release <chat>` возвращает
   бота; `/dayoff 15.06 Ремонт` — день закрыт, `/dayopen 15.06` — открыт;
   в «💊 Услуги» → карточка услуги интервал «🔁 Повторный визит» переключается
   кнопкой и сохраняется.

## Если что-то пошло не так

- **Docker не поднимается** (демон не отвечает, `WslService` отключён — живой
  случай 27.07.2026, дважды за день). Запасной путь без Docker, если на машине
  стоит нативный PostgreSQL: поднять свой кластер на том же порту 5434 —

  ```bash
  PGBIN="/c/Program Files/PostgreSQL/18/bin"
  "$PGBIN/initdb" -D "$LOCALAPPDATA/navbat-pg/pgdata" -U postgres --pwfile=<файл с паролем navbat_dev>
  "$PGBIN/pg_ctl" -D "$LOCALAPPDATA/navbat-pg/pgdata" -l pg.log -o "-p 5434" start
  "$PGBIN/createdb" -h 127.0.0.1 -p 5434 -U postgres navbat
  "$PGBIN/psql" -h 127.0.0.1 -p 5434 -U postgres -d navbat -f docker/init.sql
  psql ... -c "ALTER DATABASE navbat SET timezone TO 'UTC'"   # иначе часть тестов красная
  alembic upgrade head && python -m navbat.onboard --demo
  ```

  PGDATA держать вне `C:\WINDOWS\TEMP`: уборщик системного temp сносит пустые
  служебные каталоги кластера, и он перестаёт стартовать (`could not open
  directory "pg_notify"`).
- Бот молчит → `python -m navbat --check`; чаще всего не поднят Docker.
- Чеклист зелёный, а бот отвечает «запись временно приостановлена» → это была
  старая версия чека; актуальная показывает строку «рубильник: пауза бота».
- «Не понял» на нормальной фразе → запущено без `--real` (фикстурный NLU знает
  только тестовые фразы).
- Напоминание не пришло → офсеты считаются от времени записи: запись должна быть
  дальше в будущем, чем офсет (для `--reminder-offsets 4,2` — минимум через
  4 минуты).
- **Карточек ленты (✅/❌/🔄) нет в чате** → чат не в списке админ-чатов клиники,
  либо его добавили УЖЕ после старта бота: список читается только при запуске —
  перезапустите процесс. Проверка — строка «админ-чат» в `--check`.
- **🌙 нет у карточки** → запись оформлена в рабочие часы клиники; пометка
  ставится только вне их (до 09:00, после 18:00, закрытый день).
- **Свайп-ответ возвращает «Отвечайте реплаем на алерт эскалации или карточку
  💬»** → реплай был на карточку ленты, на сообщение консоли или на алерт старше
  7 дней (якоря ответа живут неделю, потом их чистит ретеншен). `/forget` тоже
  рвёт эту связь — отвечать больше не на что.
- Свайп-ответ фото или голосом не уходит: канал текстовый, бот ответит
  «понимаю только текст».
- **`/today` пуст** → экран показывает только СЕГОДНЯШНИЕ приёмы; запись из
  акта 1 сделана на завтра и в него не попадает.
- **⏳ не появляется** → напоминание по этой записи ещё не уходило, либо приём уже
  начался (ждать ответа не о чем — значок снимается), либо пациент нажал
  «Приду» и там теперь ✅.
- **Утренняя сводка не пришла** → до 08:30 по клинике; либо она уже уходила
  сегодня; либо на сегодня нет ни одной записи — пустым днём бот не будит.
- **В `/stats` нет строк «🔁 Возврат пациентов» / «⭐ Оценки пациентов»** →
  прогнать `python -m navbat.onboard --demo-history` (сеет и журналы; версии
  до 08.2026 их не сеяли). `--check` ловит это отдельной строкой. Нет только
  «🔔 в очереди» → норма: очередь не сеется, витрина не показывает нулей.
- «Где вы находитесь?» отвечает меню → не задан адрес (`onboard --address`).
- В карточке «ℹ️ О клинике» нет оплаты или телефона → поля не заданы
  (`onboard --payment` / `--phone`; пустое значение очищает поле).

## Что говорить про деньги

- Бот записывает, пока клиника спит: в `/stats 7` видно, сколько записей пришло
  вне рабочих часов — это пациенты, которых раньше забирал автоответчик
  конкурента.
- Неявки: напоминание с кнопкой отмены освобождает слот заранее — в сводке это
  «предотвращено неявок + сумма». Одна спасённая запись окупает месяц
  обслуживания.
- Возврат пациентов: через полгода после чистки бот сам зовёт на осмотр, и
  запись идёт в один тап. Это выручка из уже оплаченной базы — те, кто просто не
  вспомнил. В `/stats` видно «приглашений N, вернулось M» с суммой: канал
  измеряется, а не «мы им как-то звонили».
- Перехват отзывов: оценку спрашивают у всех, но публичную ссылку получают
  только довольные, а недовольный приходит алертом владельцу — с возможностью
  ответить ему тут же. Один перехваченный отзыв в 2ГИС стоит дороже года
  обслуживания.
- Лист ожидания: когда слотов нет, пациент жмёт «🔔 Сообщить, когда
  освободится». При любой отмене бот САМ присылает освободившийся слот первому
  в очереди — записаться в один тап. Пустой слот = потерянные деньги.
- «Эскалаций: 0» — администратора бот дёргает только по прямой просьбе
  пациента. При этом пациент никогда не в тупике: до живого человека всегда один
  тап, а владелец отвечает ему прямо из админ-чата свайпом. Всё остальное
  (наличие, цены, адрес, часы, оплата, телефон, перенос, отмена) бот закрывает
  сам.
- /stats — не просто счётчик: владелец видит динамику, кто из врачей приносит
  деньги и какая услуга хит. Это аргумент «вы управляете клиникой по цифрам», а
  не «у вас есть бот».
- Себестоимость ИИ: ~30–100 тыс сум/мес на клинику — копейки против одной
  потерянной записи.
- Модель: разовая настройка + ежемесячное обслуживание («мы держим и
  обслуживаем вашего администратора»).
- Дальше: пилот 2 недели бесплатно → смотрим цифры /stats вместе.
