Бот в Telegram, записывает пациентов 24/7 на узбекском и русском.

## Архитектура (карта для быстрого старта)

Принцип: «LLM — рот, код — мозг» — все решения детерминированы, NLU только
извлекает слоты. Слои (поток сообщения сверху вниз):

- **Вход (`telegram/`).** `transport.py` (polling/webhook) → durable-очередь
  `queue.py` (таблица message_queue, UNIQUE(clinic_id, update_id), двухфазный
  клейм + SKIP LOCKED → порядок per-chat, переживает рестарт). `worker.py`
  тянет из очереди, перехватывает админ-команды (авторизация по членству в
  `clinic.tg_admin_chat_ids`), нумерует callback-кнопки (>64 байт → map в
  `conversation.context['tg_actions']`), зовёт диалог. `api.py` — тонкий
  httpx-клиент Bot API; `escalation.py` шлёт алерты ВСЕМ админ-чатам.
  ИНВАРИАНТ КНОПОК: map ОДИН на чат и перезаписывается ЦЕЛИКОМ каждой
  отправкой кнопок. Поэтому кнопка, живущая дольше одной отправки
  (напоминание висит до приёма, пуш очереди — часами, выход из заморозки —
  пока ждут админа, альтернативы вытесненной записи из синка — до приёма),
  обязана нести действие сама: сырые префиксы в
  `worker.RAW_CALLBACK_PREFIXES` (+ `UNNUMBERED_PREFIXES` для админских).
  Нарушение этого правила уже приводило к отмене ЧУЖОЙ записи — новую
  долгоживущую кнопку добавлять только сырой и в лимит 64 байта.
  ВТОРАЯ ПОЛОВИНА ИНВАРИАНТА (стоила отдельного круга ревью): сырой
  callback — это ВХОД ОТ КЛИЕНТА. Он обязан нести СВОЙ субъект (запись, а
  не «то, что сейчас в контексте»: контекст один на чат и перезаписывается
  следующим сценарием) и проверять его на месте — принадлежность чату и
  свежесть времени. Образцы: `attend:`/`remind_cancel:<uuid>`,
  `wl:take:<id>:<минуты>`, `reslot:<uuid>:<минуты>`.
- **Диалог (`dialog/`).** `fsm.py` — роутер `DialogEngine` (входные точки,
  /start+меню до NLU, детекторы просьбы человека/наличия/FAQ, маршрутизация
  интента, callback-actions) поверх mixin'ов сценариев `booking_flow`/
  `reschedule_flow`/`cancel_flow`/`calendar_flow` (выбор даты, day-view;
  чистое view — `calendar_view.py`) + общих `shared_helpers`;
  константы/regex-детекторы — `dialog_common.py`. Состояние —
  типизированный `DialogContext` (`conversation.py`), персист в JSONB (поле
  `extras` хранит adapter-ключи tg_actions). Весь доступ к БД — через
  репозитории (`*_repo.py`, `patients.py`); в fsm НЕТ сырого SQL.
  Тексты — `replies.py` (TEMPLATES ru/uz, HTML-разметка; `t()` сам
  экранирует подстановки — пациентские пути шлются с parse_mode=HTML,
  алерты эскалаций plain). Строки админ-консоли — `telegram/admin_texts.py`
  (`at()`, `Reason` — причина алерта рендерится на языке ПОЛУЧАТЕЛЯ).
- **Расписание (`scheduling/`).** `engine.py` — hold/confirm/cancel/reschedule;
  занятость гарантирует БД (exclusion constraint с буфером в выражении) +
  advisory-lock на врача (анти-дедлок), код занятость не проверяет.
  `expected_start` в cancel/reschedule — сверка «запись не изменилась с
  момента снимка». `calendar_rules.py` — сетка слотов из
  working_intervals/праздников.
- **Календарь (`calendar/`).** `sync.py` — reconciliation-синк с Google
  (ручные события вытесняют ботовские с авто-переносом одной транзакцией),
  `guard.py` — freeBusy-guard перед confirm, `sync_loop.py` — цикл с алертом
  при затяжном сбое, `watch.py` — push-каналы.
- **NLU (`nlu/`).** `schema.py` (Extraction + `SERVICE_KEYS` — единый источник
  услуг), `extractor.py` (Fake/интерфейс), `openai_extractor.py`/
  `gemini_extractor.py` за `fallback.py`, `wrappers.py` (деидентификация
  телефонов перед LLM, дневной token-cap, метрика дрейфа, рубильник).
  Промпт — `src/navbat/nlu/prompts/system.md`, копия для харнесса —
  `spike_nlu/prompts/system.md` (тест `test_prompt_sync` следит, чтобы копии
  не разъехались: однажды правка доехала только в одну).
- **Фон + супервизор.** `reminders.py` (напоминания через reconciliation из
  appointment, переживают рестарт; матчер листа ожидания; вечерний дайджест
  всем админам), `retention.py` (чистка >90 дней). `supervisor.py`
  (`python -m navbat`) — транспорт+воркеры+календарь+напоминания одним
  процессом + надзор `supervise_threads` (смерть потока = алерт владельцу и
  остановка процесса, чтобы контейнер поднялся заново); `--check` —
  преддемо-чеклист. Онбординг — `onboard.py`.
  ПРАВИЛО ФОНА: фоновый поток НЕ переписывает `conversation` пациента —
  слепой read-modify-write затирал то, что пациент делает прямо сейчас
  (записывало на чужую услугу). Всё нужное кнопка несёт в себе.
- **Мультитенант + крипта (`db/base.py`, `crypto.py`).** Каждая транзакция
  ставит `app.clinic_id` (SET LOCAL); RLS FORCE на всех арендных таблицах
  изолирует клиники (глобальные без RLS ровно две: `alembic_version` и
  `nlu_prompt` — каталог промптов, tenant-данных не содержит); приложение
  под непривилегированной ролью navbat_app. Имена — AES-256-GCM; телефон
  хранится ОБОИМИ способами: SHA-256-хэш с per-clinic солью (поиск) и
  AES-256-GCM (нужен владельцу в календаре). Все шесть шифрованных колонок
  перечислены в `rotate_key.ENCRYPTED_COLUMNS` — новая колонка обязана
  попасть туда, иначе ротация ключа её осиротит.

## Окружение и команды

- Репозиторий: https://github.com/RiobVO/Stomat (origin). Коммиты пушить,
  не копить локально.
- **БД (порядок важен).** Штатно: `docker compose up -d` → postgres :5434
  (5433 занят соседним проектом; Docker Desktop может быть выключен —
  стартануть и дождаться демона). Запасной путь на Windows — нативный
  PostgreSQL 18, PGDATA `%LOCALAPPDATA%\navbat-pg\pgdata`:
  поднимать ТОЛЬКО `postgres.exe -D <PGDATA> -p 5434` ФОНОВОЙ задачей.
  `pg_ctl start` без `-W` ждёт готовности, ловит таймаут инструмента, harness
  убивает job — постмастер выживает, но все его backend'ы падают с
  0xC0000142 и кластер уходит в shutdown на первом коннекте. Снятие фоновой
  задачи гасит базу. Через `!` из промпта пользователя постмастер поднимать
  БЕСПОЛЕЗНО: команда идёт через ту же сессию и умирает по двухминутному
  таймауту (проверено 31.07). Нужен кластер, переживающий сессию, — только
  отдельный терминал вне Claude Code. Обязательно `ALTER DATABASE navbat SET timezone TO 'UTC'`
  (уже сделано) — иначе три календарных теста красные на +05:00 vs +00:00.
  PGDATA держать ВНЕ C:\WINDOWS\TEMP: уборщик системного temp сносит пустые
  служебные каталоги кластера (пропавший `pg_tblspc` лечится `mkdir`).
- Секреты: локальный `.env` в корне (gitignored) — NAVBAT_TG_TOKEN,
  NAVBAT_TG_ADMIN_CHAT и пр.; грузится автоматически (`navbat/envfile.py`)
  в supervisor, onboard и demo. Окружение главнее файла. У пользователя
  содержимое .env не спрашивать.
- **Тесты**: `python -m pytest` (полный сьют, ~2 мин); одиночный —
  `python -m pytest tests/test_x.py::test_y -q`, по подстроке — `-k имя`.
  Lint/format-тулинга нет (в pyproject только pytest). Конкурентные тесты —
  гонять сьют 5–10 раз перед «готово», одиночный прогон дедлоки не ловит.
  Параллельный pytest против общей базы ЗАПРЕЩЁН (TRUNCATE-фикстуры рушат) —
  субагентам pytest не поручать. БОТА ГАСИТЬ перед полным прогоном: фикстуры
  чистят базу и рвут FK живого процесса. CI: GitHub Actions ×3 на каждый push.
- **После прогона тестов демо стёрто** (pytest TRUNCATE'ит всю базу, включая
  токен): `python -m navbat.onboard --demo`, затем `--demo-history` для
  витрины /stats. Финализатор сьюта пытается сделать это сам. GCal-привязка
  и refresh-токен при этом гибнут — для календарной части показа нужен
  повторный `python -m navbat.calendar.auth` (клик пользователя в браузере).
- ВСЯ СИСТЕМА: `python -m navbat` (супервизор; `--check` — преддемо-чеклист;
  `--real` — платный NLU, только по явной команде; `--reminder-offsets 4,2` —
  минуты, для демо). Два процесса на один TG-токен = 409 Conflict.
- Онбординг: `python -m navbat.onboard` (--demo | --demo-history | --tg-token |
  --doctor +--calendar | --address/--payment/--phone |
  --prompt-upload FILE [--note] | --prompt-pin <N|file> | --import-calendar |
  --list | --add-admin/--remove-admin).
  Выходные дни — /dayoff в админ-чате, не онбординг.
- Демо диалога в консоли: `python -m navbat.demo` (фейковый NLU, без API).
  Сценарий показа и чеклист тест-диалогов — docs/DEMO.md.
- NLU-харнесс: `cd spike_nlu; python eval.py` (ДЕНЬГИ — по явной команде).
- Живой тык в реальном Telegram: Telethon залогинен
  (`spike_nlu/.harvest.session`). Драйверы класть в `live_poke/` — каталог
  в .gitignore, НЕ коммитить. Аккаунт пользователя совпадает с админ-чатом:
  для пациентского пути временно `onboard --remove-admin`, потом вернуть и
  ПЕРЕЗАПУСТИТЬ бота (список админ-чатов читается только при старте).
- Команды админ-чата: /stats [7|30], /release <chat>, /dayoff DD.MM [причина],
  /dayopen DD.MM, /forget <chat>, /pause [причина], /resume, /llm on|off.
  Плюс кнопочная консоль (услуги, врачи, расписание, выходные, превью
  «глазами пациента»); язык консоли — ru/uz, переключается кнопкой.

## Что проверено (факты, не трогать)

- Модель: gpt-4o-mini. Тянет узбекский/русский/смешанный. Nano-модели не тянут.
- NLU на РЕАЛЬНЫХ сообщениях (40 живых): core-5 ~80–82%; по полям (весь сет
  410): intent 91%, service 89%, date 94%, time 99%; is_medical 97.5% на real.
  Few-shot из 25 реальных примеров дал устойчивый плюс за $0.
- Харнесс, данные и конвенции разметки: `spike_nlu/` (eval.py, prompts/system.md,
  data/messages.jsonl — 410 размеченных, из них 40 real; holdout_v1.jsonl — 134).
- Стоимость: ~$0.26 / 1000 сообщений (основная статья расходов — хостинг).
- Известная дыра: book↔question на косвенных вопросах о наличии («есть время
  сегодня?») — модель уходит в question. Прикрывается на уровне FSM: на вопрос
  о наличии бот ВСЕГДА отвечает слотами. Промпт под это НЕ дожимать (подгонка
  под тест на малой выборке). Реальных сообщений мало — добрать на пилоте.

## Принятые решения (конвенции)

- LLM — рот, код — мозг. Все решения (слоты, даты, переходы) — детерминированный
  код. LLM извлекает относительную ссылку времени; абсолютную дату считает код.
- intent enum строго 5: book|reschedule|cancel|question|other, форсится strict
  json_schema. Выдуманные значения (medical/kids/greeting) запрещены.
- Симптом без услуги → book + service:checkup (это лид, не «медицинский
  вопрос»). Медицинский дисклеймер — код-слой по флагу is_medical, НЕ интент.
- Услуги (canonical, 9): cleaning, extraction, filling, crown, implant, checkup,
  xray, braces, whitening. «consultation» — алиас checkup. Оплата/рассрочка →
  question + service:null.
- date_ref: today|tomorrow|after_tomorrow|next_week|weekday_*|explicit_DD.MM|null.
  Срочность («срочно», «hozir», «tez yordam») → today.
- Телефон пациента — ТОЛЬКО кнопкой «Поделиться контактом» (без fallback на
  ручной ввод), принимается только собственный контакт; номер любой страны
  (E.164 7–15 цифр). Текст на шагах имени/телефона в NLU не уходит (PII),
  кроме вопросоподобного.
- Эскалация — минимум обращений к админу: 🔴 только прямая просьба человека
  (детектор до NLU) или 2×сбой confirm; прочее — «не понял»+меню/повтор шага
  кнопками; 🟡 FYI раз в день («нет слотов»); ⚪ дайджест (вопросы без ответа).
  FAQ-слой без LLM: часы/адрес/цены/оплата/телефон. Заморозка не вечна: /start
  пациентом, кнопка «Вернуться к записи» или /release в админ-чате.
- Вход кнопочный (button-first): /start → выбор языка → постоянное reply-меню;
  label'ы меню перехватываются точным матчем ДО NLU (ноль токенов на happy
  path). Свободный текст — LLM-fallback. Спека: docs/superpowers/specs/
  2026-06-06-button-first-menu-design.md.
- Fallback-LLM: OpenAI → Gemini (включается наличием GEMINI_API_KEY). Аутэйдж =
  ProviderDownError (сеть/5xx/429); кривой JSON и обрезанный ответ failover НЕ
  триггерят — это путь мягкой деградации «не понял».
- Метрика NLU-дрифта: failures/repairs в llm_usage, алерт при >20% сбоев за
  день (≥20 СООБЩЕНИЙ). Знаменатель — `requests - repairs`, а не requests:
  тот считает вызовы API (repair и запасной провайдер тоже), и repair
  разбавлял бы долю вдвое ровно тогда, когда модель плывёт. Тот же
  знаменатель у `/health`. «День» везде локальный, клиники: дедуп алертов
  по `date.today()` процесса расходился с ним на пять часов. Промпт можно
  пинить из БД (nlu_prompt + clinic.nlu_prompt_version; NULL = встроенный).
- Приватность: /forget анонимизирует пациента (записи остаются обезличенными,
  будущие НЕ отменяются); retention чистит очередь/диалоги/вопросы старше
  NAVBAT_RETENTION_DAYS=90 раз в день. ДВА исключения, оба обязательны:
  диалог чата с ПРЕДСТОЯЩЕЙ записью не удаляется, а вычищается до одного
  поля `lang` (язык чата живёт только в conversation.context — без него
  напоминание уходит узбеку по-русски); ответ на шаге «как вас зовут»
  стирается из message_queue сразу, как диалог его распознал
  (`queue.redact_message_text`) — это сообщение ЦЕЛИКОМ имя, ждать ретеншена
  ему незачем. Карта данных — docs/PRIVACY.md.
- Деньги в витрине: отмена из напоминания (actor='reminder') = «предотвращено
  неявок + сохранено сум» в /stats и дайджесте. Про «пуста ли витрина»
  спрашивать только `stats.collect_stats` — своя копия условий расходилась
  с витриной четырежды.
- Стек: Python 3.12, PostgreSQL, SQLAlchemy + Alembic, pytest. Без Redis.
- Коммерция: разовая настройка + месячное обслуживание (docs/OFFER.md).
